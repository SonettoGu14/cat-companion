# 着色器里发生了什么

!!! abstract "这一页回答什么"
    一个像素的颜色到底从哪来、法线贴图为什么是蓝色，以及受击闪白、溶解、地面指示器为什么是
    三种不同性质的着色器工作。

## 一屏讲完管线

画一个物体要过四个阶段：

```text
顶点 ──▶ 顶点阶段 ──▶ 光栅化 ──▶ 片元阶段 ──▶ 输出合并 ──▶ 屏幕
        （每顶点一次）  （三角形       （每像素一次）   （深度、混合）
                         → 像素）
```

1. **顶点阶段** —— 每个顶点跑一次。把顶点从物体空间搬到摄像机看得见的空间，并把数据往下传：
   UV、法线、世界坐标。
2. **光栅化** —— 固定功能的一步。算出每个三角形盖住哪些像素，并把传下来的数据在三角形内部插值。
3. **片元阶段** —— 每个*候选*像素跑一次。拿到插值后的值，返回一个颜色（可选返回 alpha）。
   这是你在 Shader Graph 里写的那部分，也是最贵的那部分。
4. **输出合并** —— 深度测试、混合、写入。

上面那个不对称要记住：**顶点阶段按顶点跑，片元阶段按像素跑。** 一个 5000 顶点、占了大半屏的
模型，时间几乎全花在片元阶段。

## Material、Shader、Shader Graph —— 三样不同的东西

| 词 | 是什么 | 存什么 |
| --- | --- | --- |
| **Material** | 一个资产：存好的一袋值 | 颜色、贴图、数字 |
| **Shader** | 一个程序 | 指令 |
| **Shader Graph** | 写着色器的编辑器 | 一张会编译成着色器的图 |

Material 本身没有「外观」。它存值；着色器决定这些值是什么意思。所以两个 Material 用同一个
着色器、看起来不一样；也所以改一个被共享的 Material，所有用到它的物体一起变。

## 片元着色器就是一个函数

把仪式感去掉，片元阶段就是：

```hlsl
float4 frag(Varyings i) : SV_Target
{
    float3 colour = ...;      // 你算的一切
    return float4(colour, 1); // 这个像素变成什么
}
```

Master Stack、节点、Blackboard，全都只是写这个函数的办法。「这个着色器在干什么」这个问题，
永远是「吃这些输入，吐出什么颜色」。

## 光照从哪来

受光着色器拿到的不是一个成品颜色。它拿到表面的**基础色**（albedo，材质的漫反射底色），
再乘以光照：

```hlsl
float3 N   = normalize(i.normalWS);
float3 L   = normalize(lightDir);
float  ndl = saturate(dot(N, L));

float3 lit = baseColour * ndl * lightColour;
```

`dot(N, L)` 就是[向量与点乘](../maths/vectors-and-dot-product.md)里那一项：表面正对光时是
1，明暗交界处是 0，再往下被夹住。更复杂的光照模型里，高光、环境光、阴影，都是加在这一行**之上**，
而不是替换它。

## 法线贴图为什么是蓝色

这是课上停不下来讲的问题，所以放这。

法线是一个方向，分量在 −1…1。贴图存颜色，范围 0…1。要把方向存进贴图，就要重映射：

```text
存进去的值 = 方向 * 0.5 + 0.5
```

**切线空间**的法线贴图存的是相对于表面的法线，那套坐标系里

- `x` 沿着表面（切线），
- `y` 横过表面（副切线），
- `z` **垂直于表面朝外**。

完全平的表面，法线是 `(0, 0, 1)` —— 朝外。按颜色存就是 `(0.5, 0.5, 1.0)`，也就是那个熟悉的
**淡蓝紫色**。一张平的法线贴图几乎全是这个颜色，细节都是绕着它的小偏移。你看到一张像淡紫色石头
照片的法线贴图，看到的就是「这个表面上每一点相对于平的方向朝哪」的照片。

这也是为什么着色器里读回来要用 `* 2 - 1`：贴图给 0…1，数学要 −1…1。

## 三个效果，三种着色器工作

### 受击闪白 —— 改一个值，不换着色器

受击闪白不需要新着色器。着色器读一个数，比如 `_Flash`，脚本把它从 0 动到 1 再回来：

```hlsl
float3 col = lerp(baseColour, float3(1,1,1), _Flash);
// 或者整面闪的便宜写法：
col += emissionColour * _Flash;
```

值的混合是 `lerp`；时间节奏归 C#，不归着色器。这是通用套路：**着色器暴露一个控制量，
游戏代码去驱动它**。

### 溶解 —— 噪声、阈值、一刀切

溶解是一张噪声贴图和一个移动的阈值比较：

```hlsl
float noise = SAMPLE_TEXTURE2D(_NoiseTex, sampler_NoiseTex, uv).r;
float threshold = _DissolveAmount;          // 效果过程中 0 → 1
clip(noise - threshold);                    // 直接丢弃片元，不是混合
```

`clip`（alpha clip）把片元整个扔掉，所以洞是硬边的，物体能被一块块切走。注意它**不是** alpha
渐变：渐变让整个物体变半透明幽灵，clip 让物体一块块消失。

### 技能指示器 —— 地面上的透明贴花

地面指示器通常是**无光照、透明**的方片或贴花，填充由 UV 到中心的距离驱动：

```hlsl
float d = distance(uv, float2(0.5, 0.5));
float fill = step(d, _Radius);              // 想要软边就用 smoothstep
float4 col = _Colour * fill;                // 无光照：完全没有 dot(N, L)
```

三个后果值得知道：无光照（刻意忽略场景光照）、不写深度（它贴在地上，不能挡住地面），以及它一次
盖住很多像素 —— 这就是下一节。

## 着色器的成本

成本大致是：

```text
成本 ≈ 覆盖的像素数 × 每像素指令数
```

于是三条规则：

- **小物体、重着色器** —— 没事。像素少。
- **全屏效果、极简着色器** —— 贵，因为「极简」也要乘两百万个像素。
- **透明** —— 比看起来贵：透明片元没法提前剔除，好几层透明叠在一起（指示器、溶解、闪白同时上）
  全都要画一遍，这就是 **overdraw**。

## 自检

??? question "1. 一个模型只有 100 个三角形，但铺满屏幕。成本主要来自哪？"
    几乎全在片元阶段：整屏的像素都要跑逐像素着色器。这个尺寸下三角形数量无关紧要。

??? question "2. 为什么 `clip(noise - threshold)` 的边比「alpha 乘 noise」硬？"
    `clip` 是丢弃片元，要么全画、要么不画，边界就是噪声阈值本身。乘 alpha 会让物体整体半透明、
    边缘发虚，而且用不了只写深度的那些技术。

??? question "3. 法线贴图看起来是淡紫色。这个颜色到底编码了什么，哪个空间？"
    每像素一个方向，从 −1…1 重映射到 0…1，在切线空间里 —— `z` 朝表面外，所以平的法线是
    `(0.5, 0.5, 1)`，即淡紫色。

??? question "4. 地面指示器为什么做成无光照？"
    因为它是玩法信号，不是表面。暗房间和太阳底下必须读起来一样；让它跟着场景光照变，警告就不可靠了。
