# 网状叙事

「分支叙事」不是一种结构，而是一族结构，共四种，做起来的成本能差十倍。

```
线性        A ── B ── C ── D                    所有人都看到全部内容

收束        A ── B ── C ── D                    分叉，然后再合并
                  └── B' ──┘

树状        A ── B ── C                         分开之后再也不相遇
                  └── D ── E

网状        场景 + 状态                          同样的场景，不同的含义
```

## 各自的成本

**线性**是免费的，而且名声被冤枉了。故事够强就不需要选择，《传送门》是线性的，没人说它故事差。

**收束**是商业上的标准答案。玩家分叉、感觉到自己选了，但在内容预算爆炸之前路线又合并回来。
《神秘海域》和绝大多数 3A 都是这个：选择改变的是语气和接下来十分钟，然后主线继续。

**树状**是「选择」最诚实的版本，也是成本最容易被低估的版本。三个决策点、每个两个选项，就是
八条路线。你的写作预算被路线数一除，而玩家永远只看到其中一条 —— 所以每条路线只有线性版本
十分之一好。

**网状**放弃分开的场景，把变化放进**状态**里。场景是同一批，变的是玩家知道什么、能说什么、
会注意到什么。《极乐迪斯科》是极端例子：你的技能改变能说的句子，甚至改变世界给你看的东西，
而情节骨架是稳定的。

## 最划算的一招

**延迟兑现**。现在便宜地分叉，以后在一个地方一起付账。第一章的一句台词，改变第四章的一场戏。
你只多写了一场戏，不是多写了一整幕。

**枢纽与循环**。《Hades》每次跑同一套地牢结构，故事在两次轮回之间推进。重复的部分是系统，
叙事的部分是外包装，而外包装很便宜。

## 选能承载主题的最便宜结构

只问一个问题：**为了让这个故事成立，玩家必须决定什么？**

如果答案是「什么也不用决定，他需要看见」，就写线性，把预算花在场景上。如果是「要不要相信她」，
你需要一个真正的分岔 —— 不是一个十二个。

能救项目的两条规矩：

1. **先写状态表，再写场景。** 到这个节点玩家可以知道什么？他知道了会改变什么？写不出这张表，
   你有的不是分支故事，是一个愿望。
2. **不要承诺你付不起的后果。** 《质量效应 3》的结局被骂，不是因为结构差，而是因为三部曲花了一
   百小时教玩家「选择会算数」，而最后一个选择没有算数。

## 自检

??? question "三个二元决策，完整树状产生几个结局？这对预算是意味着什么？"
    八个。每条结局只拿到线性版本大约八分之一的写作、美术和测试时间 —— 这就是为什么绝大多数
    实际发售的游戏最后都选择收束。

??? question "为什么「枢纽 + 循环」对叙事来说很便宜？"
    因为最贵的部分（循环本身）是一个建一次、反复使用的系统，叙事只需要为「两次轮回之间改变了
    什么」写内容。

??? question "你的设计承诺「选择很重要」，但预算只够做收束。诚实的补救是什么？"
    让选择改变某种看得见、够得着的东西 —— 语气、一段关系、一场戏 —— 然后让主线合并回来。
    把承诺兑现得小一点，好过把承诺辜负得大一点。
