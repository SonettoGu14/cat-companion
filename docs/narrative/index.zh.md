# 叙事手法

游戏里的故事是用一批比游戏古老得多的零件拼起来的：一个把所有人往前拽的目标、一条人物
走过的路径、一个有自己的规则的世界，以及一句话把整个想法说清楚的本事。这一节把这些零件一个个拆开。

它不是写作课，也不是文学理论。每页只做四件事：说清一个装置、指一个你真能玩到的游戏里它怎么
起作用、说它怎么失效，然后结束。

## 页面

**情节层** —— 塑造事件顺序的那几个装置：

| 页面 | 回答什么 |
| --- | --- |
| [麦高芬](mcguffin.md) | 为什么所有人都想要的那个东西可以几乎是什么都行 —— 以及什么时候这没问题 |
| [英雄之路](hero-journey.md) | 那十二个阶段是什么，以及为什么照抄它会让每个游戏都变成同一个故事 |
| [高概念](high-concept.md) | 一句话说完整个游戏，并且检验这句话值不值得说 |

**世界层** —— 这些事件发生的地方，它自己的规则是什么：

| 页面 | 回答什么 |
| --- | --- |
| [世界观](worldbuilding/index.md) | 设定作为一套规则：魔法能做什么、谁控制它、代价是什么 |
| [高魔](worldbuilding/high-fantasy.md) | 谁有资格用魔法，以及为什么不是人人都在用 |
| [赛博朋克](worldbuilding/cyberpunk.md) | 你的身体属于谁，以及谁在看着你 |
| [洛夫克拉夫特式](worldbuilding/lovecraftian.md) | 你懂得太多之后会发生什么 |

## 一页怎么读

先读前两节。例子已经讲明白了，就直接跳到「自检」做题。答不出来的那题会告诉你该重读哪一节。

## 开始之前一句提醒

这些页面不能把故事变好。它们只是词汇和检查项：让你能对自己的设计问一个比「有不有趣」更
锋利的问题。一个用对了术语但底下什么都没有的设计文档，比一个什么也没说清楚的更糟。
